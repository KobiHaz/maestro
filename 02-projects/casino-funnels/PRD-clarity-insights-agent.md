## 2. Problem Statement

- **כאב:** קשה לזהות במהירות היכן משתמשים נתקעים, לוחצים לשווא או נוטשים — בלי לצלול ידנית להמון הקלטות ב-Clarity.
- **למי:** בעל מוצר, שיווק, מפתחים שמשנים משפך (דף גלגל, אוברליי, יציאה לשותף).
- **היום:** נתונים קיימים ב-Clarity (לוח בקרה, הקלטות) אבל אין תהליך עקבי שמפיק **תובנות ממוקדות והמלצות פעולה** מהנתונים המאוגדים + מהאותות מהאתר.

---

## 3. Goals & Non-Goals

### Goals (מה נחשב הצלחה)

- דוח או הודעה תקופתית (למשל יומי/שבועי) עם **תובנות מבוססות נתונים** מ-Clarity (מדדים מאוגדים) ועם **המלצות שינוי** ברורות (עותק, UI, סדר אלמנטים).
- **מילון אירועים ותגיות** מתועד באתר — כדי לפרש התנהגות בהקשר המשפך (לא רק מספרים גלובליים).
- שמירת **היסטוריית צילומי API** (מקומית או בענן) כדי להשוות תקופות — כי ה-API הרשמי מוגבל לחלון זמן קצר.
- אפשרות **חקירה אד־הוק** (אופציונלי): שימוש ב-Clarity MCP בסביבת עבודה לשאלות טבעיות ורשימת הקלטות — כשצריך עומק.

### Non-Goals (לא בשלב זה)

- ניתוח וידאו גולמי של כל סשן בצורה אוטומטית מלאה אם אין לכך מסלול API יציב או הסכמה ברורה.
- החלפת GA4 / Meta Pixel או איחוד דוח אחד חובה לכל הכלים — כאן המיקוד הוא Clarity כמקור ראשון לסוכן.
- בניית מוצר SaaS חיצוני; המטרה היא יכולת פנימית לפרויקט/צוות.

## 4. Users & Use Cases

### Personas

- **בעל מוצר / גדלים:** רוצה «מה השתנה השבוע» ו«מה לתקן קודם».
- **מפתח פרונט:** רוצה קישור בין מדד (למשל dead clicks לפי URL) לבין רכיבים בקוד.
- **אנליסט (אם קיים):** רוצה לסנן הקלטות ולאמת השערות — דרך MCP או ממשק Clarity.

### מסעי שימוש עיקריים

1. **דוח שגרתי:** תזמון רץ → משיכת Data Export API → נירמול → מודל שפלט מובנה → שליחה לערוץ (דוא״ל, Slack, Telegram וכו׳).
2. **הכנת שינוי במוצר:** מפתח פותח PR → בודק ב-MCP «הקלטות עם שגיאות בדף X» או משווה מדדים לפני/אחרי.
3. **הרחבת מדדים:** מגדירים אירוע חדש במילון → מיישמים באתר → בדוח הבא הסוכן מפרש אותו בהקשר.

## 5. Functional Requirements (FRs)

| מזהה | תיאור |
|------|--------|
| **FR-1** | משיכה מתוזמנת של נתוני `project-live-insights` עם JWT מייצוא נתונים (פרמטרים: טווח ימים 1–3, עד שלושה מימדים) וטיפול בשגיאות (401, 429, גוף לא תקין). |
| **FR-2** | שמירת תוצאות גולמיות (JSON) עם חותמת זמן ומזהה פרויקט — לפחות להשוואה שבועית. |
| **FR-3** | מסמך **מילון אירועים ותגיות** (שם, מתי נורה, בעלים) — גרסה נשלפת לסוכן בכל ריצה. |
| **FR-4** | שלב ניתוח (כללים ו/או LLM) שמפיק פלט **מובנה**: תובנות (3–7), המלצות, רמת ביטחון, הפניה ל-URL/מימד כשקיים בנתונים. |
| **FR-5** | איסוף בצד לקוח: לפחות אירועים/תגיות במסלול המרכזי של המשפך (בהתאם למילון) — בפרודקשן בלבד אם כך מוגדר במדיניות. |
| **FR-6** | (אופציונלי) שילוב Clarity MCP לשאילתות אינטראקטיביות; לא חובה ל-CI של הדוח השגרתי. |
| **FR-7** | לוגים ללא דליפת JWT או PII בטקסט פתוח; הודעות שגיאה קצרות למפעילים. |

## 6. Non-Functional Requirements (NFRs)

| תחום | דרישה |
|------|--------|
| **אבטחה** | טוקן ייצוא רק בסודות/משתני סביבה מאובטחים; רוטציה כשעובד עוזב; ללא commit לקוד. |
| **ציות** | כללי Clarity (גיל 18+ לאתרים לילדים); מיסוך שדות רגישים; `consent` אם יש באנר עוגיות — לפי מדיניות משפטית. |
| **אמינות** | התאוששות מכשלון API; לא לאבד דוח אם המודל נכשל — fallback לסיכום כללי או התראה. |
| **עלות** | תקרת קריאות API (10/יום לפרויקט) — תכנון ריצות (מימדים לסירוגין, לא כפל קריאות מיותר). |
| **תצפית** | מעקב אחר הצלחת ריצה, משך, כשלונות (לוג או מערכת קיימת). |

## 7. Data & Integrations

### ישויות (רמת גבוהה)

- **צילום ייצוא:** גוף JSON גולמי + `fetched_at`, `num_days`, מימדים.
- **תובנות:** מסמך/רשומה עם תאריך, גרסת מילון, טקסט מובנה.
- **מילון מדדים:** גרסה, רשימת `event` / `tag` עם תיאור עברי.

### מערכות חיצוניות

| מערכת | אינטגרציה | מגבלות |
|--------|-----------|---------|
| **Clarity Data Export (REST)** | `GET .../project-live-insights` + Bearer JWT | 1–3 ימים, 10 בקשות/יום, 1000 שורות, ללא pagination |
| **Clarity (דפדפן)** | תגיות, אירועים, מיסוך, אופציונלית `consent` / `upgrade` | לא למשיכת היסטוריה מהשרת שלנו |
| **Clarity MCP** | `@microsoft/clarity-mcp-server` + אותו טוקן | לשימוש אינטראקטיבי; לוודא עדכניות מול תיעוד מיקרוסופט |
| **ספק LLM** | API לניתוח טקסט (או כללים בלבד ב-MVP) | עלות, מדיניות נתונים, איסור שליחת PII |

## 8. Risks, Assumptions, Open Questions

### סיכונים

| סיכון | השפעה | הפחתה |
|--------|--------|--------|
| שינוי API או MCP מבית מיקרוסופט | שבירת אוטומציה | גרסאות צעד, בדיקות עשן, מעקב אחר Learn |
| מודל מייחס סיבתיות שגויה | החלטות מוצר שגויות | פרומפט עם «השערות בלבד»; דרגות ביטחון |
| עומס אירועים באתר | רעש ב-Clarity | מילון מצומצם, שמות עקביים |

### הנחות

- יש גישת אדמין לפרויקט Clarity ליצירת טוקן ייצוא.
- יעד הדוח הוא תובנות והמלצות — לא החלטות משפטיות אוטומטיות.

### החלטות מוצעות (לאישור בעלים)

| נושא | המלצה | הערה |
|------|--------|------|
| ערוץ פלט | התחלה ב-**קובץ / ארטיפקט ב-CI** + אופציונלי **טלגרם** אם כבר יש בוט וסודות | אחיד לפרויקטים קיימים; ניתן להוסיף Slack אחר כך |
| MVP מול LLM | **שלב א׳:** כללי סף + טבלת סיכום מובנית מתוך ה-JSON; **שלב ב׳:** שכבת LLM על אותו קלט | מפחית עלות ותלות בפרומפט לפני שיש נפח נתונים |
| שמירת צילומי API | **אובייקט סטור** (S3 / R2 / מקביל) או **ארטיפקט GitHub Actions** לטווח קצר; שמירה **30–90 יום** כברירת מחדל | לא ב-repo ציבורי; ללא PII בקובץ |

### שאלות שעדיין דורשות וידוא

- חוזה / DPA עם ספק ה-LLM אם נשלחים קטעי JSON מזוהים לדומיין.
- האם נדרש באנר הסכמה שמזין `clarity('consent')` לפי ייעוץ משפטי.

## 9. Success Metrics

- **ראשי:** הפחתה מדידה במדדי חיכוך (dead / rage / שגיאות סקריפט) לפי URL או מגמה חיובית לאורך 4 שבועות — אחרי יישום המלצות שאושרו.
- **תהליך:** ≥90% מהריצות המתוזמנות מסיימות עם פלט תקין (או התראת כשל ברורה).
- **שומרי גדר:** לא ירידה ב-coverage של מיסוך; לא הוספת מזהים אישיים ל-Clarity בלי אישור משפטי.

## 10. Dependencies & Rollout

### תלויות

- טוקן Clarity Data Export; מפתח API ל-LLM (אם נבחר).

## 12. נספח ב׳ — סכימת פלט מומלצת לסוכן

פלט יציב (JSON) מאפשר דוחות, בדיקות, והמשך עיבוד בלי פרשנות חופשית בלבד.

```json
{
  "schema_version": "1",
  "dictionary_version": "0.1",
  "window_label": "string",
  "generated_at": "ISO-8601",
  "insights": [
    {
      "id": "string",
      "summary_he": "string",
      "confidence": "high | medium | low",
      "signals": ["metric_or_dimension_refs"],
      "suggested_actions_he": ["string"]
    }
  ],
  "alerts": [
    {
      "metric": "string",
      "severity": "info | warn | critical",
      "detail_he": "string"
    }
  ],
  "clarity_dashboard_url": "string | null"
}
```

שדות `signals` יכילו מזהים קצרים שמתאימים לשורות בייצוא (למשל שם מטריקה + מימד) — לא לכלול טוקנים או PII.
